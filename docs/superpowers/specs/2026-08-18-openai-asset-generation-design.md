# OpenAI 小鲸鱼动画资产生成设计

Date: 2026-08-18
Status: Approved in conversation; pending written-spec review

## 1. 背景与目标

本设计替换原方案中的本地 Stable Diffusion 正式生成链路。现有本地模型样片出现头身比例、鲸尾结构和动作一致性偏差，因此标准版与修长版正式动画资产改用 DeepSeek Harness 已配置的 OpenAI-compatible API 和 `gpt-image-2` 生成。

本次变更不改变既有产品范围：

- `chibi` 继续使用现有 Q 版资产；
- `standard` 仍以角色设计2、3为约四头身基准；
- `slender` 仍以角色设计5、6为约六至七头身基准；
- 标准版与修长版各 50 帧，共 100 张最终 PNG；
- 动作集合、帧数、文件名、透明画布和逻辑显示高度继续遵循已批准的三档比例设计与 manifest。

本地 Stable Diffusion 只保留为已验证但弃用的实验链路，不进入正式资产来源。

## 2. API 与凭据边界

- Base URL 从 `C:\Users\89088\.dsh\settings.yaml` 的 `llm-pi-ai.providers.openai.baseURL` 读取。
- API Key 从 `C:\Users\89088\.dsh\.credentials.yaml` 中与 `OPENAI_API_KEY` 对应的凭据读取。
- 正式图像模型固定为 `gpt-image-2`。
- 生成脚本只在进程内读取凭据；不得把 API Key 写入仓库、命令输出、生成任务、报告、日志或 Git。
- 在任何付费生成前，先探测模型列表以及图片生成／编辑端点能力；探测结果只记录模型名、端点可用性和非敏感错误。
- API 或兼容代理不支持所需图片编辑能力时立即停止，不自动回退本地 Stable Diffusion，也不批量消耗额度。

## 3. 方案选择

采用“多参考图片编辑链＋动作关键帧分层”。

不采用纯文本重绘，因为它无法可靠保持头身比例、服装零件、鲸尾结构和 50 帧动作矩阵。不采用本地模型与 OpenAI 混合出图，避免正式资产在风格和身份特征上分裂。

### 3.1 四张样片门槛

批量生成前只生成四张付费样片：

1. 标准版待机；
2. 标准版动作；
3. 修长版待机；
4. 修长版动作。

四张样片全部通过视觉检查后，才允许启动完整 100 帧批量。样片通过后可作为对应 pack 的母图或计入对应的 50 帧正式资产，因此最终正式资产总数仍为 100，而不是额外增加到 104；若不通过，只重做失败样片并调整约束，不启动批量。

### 3.2 每帧参考输入

每个请求按以下优先级提供参考：

1. 当前比例的完整三视图；
2. 当前比例已批准的正面母图；
3. 发型、头饰、鲸耳、领结、围裙图案、裙摆、鞋袜和鲸尾局部参考；
4. 对应动作的 Q 版帧；
5. 连续动作第二帧及以后使用的上一张已通过帧；
6. 当前帧相对上一帧的局部动作变化描述。

Q 版参考只定义动作、视角和表情语义。提示词必须明确：不得继承 Q 版二头身比例，不得覆盖当前 standard/slender 的脸型、服装和身体比例。

### 3.3 动作生成顺序

- 每个 clip 先生成动作首帧或关键帧。
- 首帧通过检查后，按 manifest 顺序生成后续帧。
- 后续帧同时提供母图、Q 版对应帧和上一张已通过帧。
- 只允许改变动作需要变化的局部；上一帧不得逐步累积改变角色设计。
- 每一帧记录模型、输出路径、参考文件、上一帧、提示词摘要和请求状态，便于重生成与追溯；记录中不含凭据。

## 4. 输出与后处理

OpenAI 原始输出保存在 git 忽略的追溯目录。正式输出要求：

```text
格式：PNG RGBA
画布：512 x 512
背景：完全透明
色彩空间：sRGB
逻辑显示高度：260
```

- 若接口只提供 1024×1024，使用高质量 Lanczos 缩放至 512×512。
- 优先请求透明 PNG。
- 无论接口声明何种背景，都检查 alpha 通道、四角和边缘像素。
- 若输出为不透明或背景残留，使用单会话复用的 `u2netp` 抠图；其本机批量基准约为 0.54 秒／帧。
- 后处理后必须重新检查透明边缘、白边、角色完整性、脚底基线和裁切。
- 原始响应、失败响应和后处理临时文件不得直接进入 `assets/pet-standard` 或 `assets/pet-slender`。

## 5. 样片与批量验收

### 5.1 四张样片

每张样片必须满足：

- 标准版约四头身；修长版约六至七头身；
- 深蓝到浅蓝渐变长发、固定发缝和呆毛方向；
- 蓝白女仆头饰、鲸耳／侧鳍、深蓝女仆装、白围裙鲸鱼图案；
- 领结、纽扣、袖口、裙摆金色细节、鞋袜和后腰蝴蝶结一致；
- 蓝色眼睛与固定分叉鲸尾；
- 无猫耳、普通鱼尾、写实化、年龄增长或额外性感化细节；
- 无文字、边框、家具、房间和不必要背景；
- 头饰、头发、双手、裙摆、鞋和尾鳍未裁断；
- 人体、手指、五官和尾鳍无明显畸形。

### 5.2 100 帧批量

- 每个 pack 恰好 50 帧，动作集合和每个 clip 帧数与 Q 版 manifest 一致；
- 连续帧不随机改变脸、发型、服装、手指数目、鞋型、鲸尾和当前比例；
- 脚底基线、角色中心和画布位置稳定；
- 透明背景无文字、家具、设计稿边框和明显白边；
- 所有帧通过尺寸、RGBA、alpha、命名、文件存在性和 manifest 验证后才能进入生产目录；
- 在 Helper 中以 70%、100%、140% 尺寸播放，检查裁切、跳脚、循环和实时比例切换。

## 6. 错误处理与费用控制

- 四张样片是强制费用门槛；未全部通过时禁止批量。
- 单次请求超时、限流或 5xx 使用有上限的指数退避；认证、权限、模型不存在或请求格式错误不重试。
- 每帧写入成功标记后才继续；恢复执行时跳过已校验成功的帧。
- 返回空图片、损坏图片、错误格式或不符合比例时标记失败，不覆盖已有通过帧。
- 批量阶段按 clip 提交，不并发轰炸接口；默认低并发，遇到限流自动降低。
- 不记录或猜测兼容代理的单价。生成报告记录请求数和成功／重做数量，费用由 API 提供方账单核对。

## 7. 测试与审查

- 单元测试覆盖 DSH 配置读取、凭据不泄露、任务到 multipart 请求的映射、失败重试分类、响应解码、缩放和 alpha 验证。
- 提供 dry-run：只构建请求摘要和引用列表，不发送付费请求。
- 四张样片生成后执行人工视觉审查并保留结果。
- 100 帧完成后运行 Node、Python、资产验证和 Helper 视觉验收。
- 代码任务继续遵循 TDD、任务级规格／质量审查和最终整分支审查。

## 8. 与既有计划的关系

- 比例计划 Tasks 1–3 的配置、注册表和运行时切换保持不变。
- Task 4 的参考裁切、generation jobs 和验证器保持；生成任务增加 OpenAI 请求所需的结构化引用和 dry-run 数据。
- Tasks 5–6 的“生成”实现改为本设计的 `gpt-image-2` 四样片门槛与多参考编辑链。
- Task 7 的集成、测试、Helper 播放和文档验收保持不变。
