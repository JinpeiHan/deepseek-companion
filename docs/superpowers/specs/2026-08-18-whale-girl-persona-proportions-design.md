# 小鲸鱼人格文案与三档头身比设计

## 1. 目标

本次改造在不改变 DSH 状态伴侣定位的前提下完成两项能力：

1. 建立集中式人格文案库，将用户可见角色称呼统一为“小鲸鱼”，以轻度、聪明慵懒、傲娇甜美的语气呈现状态与互动反馈，同时保留任务事实的清晰度。
2. 增加 `Q版 / 标准 / 修长` 三档角色形态。每档使用独立完整动画资产，不对单张素材进行局部拉伸；三档默认显示总高度一致。

## 2. 非目标

- 不增加第二套聊天工具、API Key、聊天历史或主动对话系统。
- 不改变 Session 选择、状态聚合、动作优先级或 DSH 生命周期。
- 不重命名 npm 包 `dsh-dafeiyu`、内部环境变量前缀或已有兼容标识。
- 不建立通用角色商城或无限制角色编辑平台。
- 不从原始参考图直接带入文字、边框、家具或背景。

## 3. 人格文案

### 3.1 集中管理

新增集中式人格文案模块，统一管理：

- 空闲、准备、思考、查找、编辑、测试、执行与结果整理；
- 等待输入、等待审批、成功、工具错误、任务错误、停止和达到上限；
- 摸头、戳一下与尾巴互动；
- 用户可见角色名称“小鲸鱼”。

现有确定性选句机制继续保留，使同一分组可提供多个变体且测试结果稳定。状态和互动文案共享同一人格规则，避免 JavaScript 与 Python 文案风格分裂。

### 3.2 语气边界

- 工作、查找、编辑与测试文案以信息清晰为先，只带轻度角色语气。
- 等待、审批、成功与点击互动可以偶尔称用户为“主人”。
- 不在每条文案中重复角色口癖。
- 不再使用“大肥鱼”作为用户可见自称。
- 项目名、阶段、待办、真实进度、错误事实和权限类型不进行角色化改写。
- 文案不能编造进度、成功、失败原因或下一步。

## 4. 三档角色形态

### 4.1 配置模型

新增配置字段：

```text
characterProportion: chibi | standard | slender
```

对应用户界面：

- `chibi`：Q版，默认值；
- `standard`：标准；
- `slender`：修长。

设计参考映射：

- Q版：`角色设计1` 与现有 Q 版动作参考；
- 标准：`角色设计2`、`角色设计3`；
- 修长：`角色设计5`、`角色设计6`。

### 4.2 设置入口

DSH 插件设置页在“角色大小”之前增加“角色形态”选项，说明为：

> 切换小鲸鱼的头身比例；三种形态保持相同显示高度和动作状态。

Helper 右键菜单增加“角色形态”子菜单。设置页与右键菜单操作同一配置值并保持同步。

### 4.3 配置与持久化

配置沿用现有数据流：

```text
DSH 设置页
  -> 插件配置 characterProportion
  -> Helper 启动环境变量或运行时配置消息
  -> Python Helper
  -> 对应角色 manifest 与帧缓存
```

启动环境变量使用：

```text
DSH_DAFEIYU_PROPORTION=chibi|standard|slender
```

本地布局存储同步保存 `characterProportion`。只有三个合法字符串可以通过归一化；其他字符串、空值、数字和布尔值回退到 `chibi`。旧配置缺少字段时默认 `chibi`，不修改原有窗口坐标、角色缩放和气泡缩放。

### 4.4 运行时切换

切换形态时：

1. 验证目标资产包 manifest；
2. 加载当前动作所需帧；
3. 保持当前真实 DSH 状态与活动分类；
4. 切换到新资产包中的同名动作；
5. 通过短交叉淡化替换画面；
6. 保持窗口位置、脚底锚点、总显示高度和气泡位置稳定；
7. 释放不再需要的旧帧缓存。

角色形态只决定资产包，不改变 Session 优先级、状态 reducer、待办进度、动作优先级、减少动态行为或互动结束后的状态恢复。

### 4.5 显示尺寸与锚点

- 三档在默认 `100%` 下具有相同逻辑显示高度。
- Q版头部占比最大，标准版约四头身，修长版约六至七头身。
- 原有 `70%–140%` 角色大小继续缩放整个角色。
- 每套 manifest 提供脚底锚点与头顶／气泡锚点，避免使用固定像素。
- 切换比例时脚底位置不跳动，气泡跟随对应头顶锚点。

## 5. 资产包架构

建议目录：

```text
assets/pet/
  chibi/
    manifest.json
    ...
  standard/
    manifest.json
    ...
  slender/
    manifest.json
    ...
```

三套 manifest 使用相同动作名称与状态映射。运行时可只切换资产包，不复制状态业务逻辑。

若选中资产包的某个动作缺失或损坏，先回退到该包的 `idle`；若整包无效，则回退到 Q 版。资产错误只记录诊断，不得导致 Helper 或 DSH 插件崩溃，也不得显示透明空窗。

| `working_command` | 4 |
| `walk_start_left` | 2 |
| `walk_stop_left` | 2 |
| `walk_start_right` | 2 |
| `walk_stop_right` | 2 |

## 7. 资产视觉规范

### 7.1 角色识别特征

所有帧必须保持：

- 深蓝到浅蓝渐变长发、固定发缝和呆毛方向；
- 蓝白女仆头饰、蓝色鲸耳／侧鳍；
- 深蓝女仆装、白色围裙及固定的小鲸鱼图案；
- 固定领结、纽扣、袖口、裙摆金色细节、鞋袜与后腰蝴蝶结；
- 蓝色眼睛和固定鲸尾分叉结构；
- 可爱的二次元鲸鱼少女身份，不变成猫耳、普通鱼尾或写实真人。

不同帧之间不得随机改变五官、手指数目、服装零件、鞋型、鲸尾、配色或当前档位的头身比例。

### 7.2 比例规则

标准版以设计2、3为约四头身基准：头部仍偏大，四肢短而完整，保持桌宠可爱感。

修长版以设计5、6为约六至七头身基准：头部相对缩小，身体、四肢和裙装增长，但不增强年龄感、不写实化、不增加设计稿之外的性感化细节。

### 7.3 导出规则

```text
格式：PNG RGBA
背景：完全透明
源画布：512 x 512
逻辑显示高度：260
色彩空间：sRGB
```

- 每套动作使用相同画布、角色中心与脚底基线。
- 不裁断头饰、头发、手臂、裙摆或尾鳍。
- 连续帧脚底不漂移，透明边缘无白边和 JPEG 污染。
- 原始参考中的文字、问号、边框、电脑、沙发、地面和房间不进入资产。
- 爱心、水滴、眩晕圈等动作必要特效可以保留。

## 8. 参考图注入与生成流程

### 8.1 结构化参考包

原始上传文件保持不变，生成兼容查看副本和用途明确的裁切参考：

```text
art-references/
  source/
  chibi/
    turnaround/
    expressions/
    poses/
    details/
  standard/
    turnaround/
    expressions/
    details/
  slender/
    turnaround/
    expressions/
    details/
  shared/
    palette/
    costume/
    tail/
```

参考裁切包含三视图、正面母图、表情栏、领结与领口、头饰、耳鳍、围裙图案、裙摆、鞋袜、后腰蝴蝶结、发尾渐变和鲸尾。

### 8.2 每帧生成输入

生成每个标准版或修长版动作帧时，向生成模型同时提供：

1. 当前比例的完整三视图；
2. 当前比例的正面角色母图；
3. 对应动作的 Q 版参考；
4. 服装、发型、耳鳍与鲸尾局部参考；
5. 统一配色参考；
6. 连续动作第二帧及以后所需的上一帧；
7. 当前帧相对上一帧的动作变化描述。

参考优先级为：当前比例三视图 > 当前比例母图 > 局部细节 > Q 版动作姿势 > 文字动作描述。上一帧用于限制局部变化，不能累积改变角色设计。

Q 版参考只提供“怎么动”和表情语义，不能覆盖标准版或修长版的头身比例与外观定义。

### 8.3 动作参考语义

上传的 Q 版图片可提供叉腰吐槽、摸鱼躺平、爱心手势、眩晕、追赶哭泣、抱臂不满、灵魂出窍、敬礼、跪坐委屈、疑惑、慵懒休息、大哭、灵光一现和得意互动等姿势与表情。生成只继承动作语义，不继承文字、家具和背景。

### 8.4 连续性流程

1. 先生成并审核当前比例的三视图和标准待机母图。
2. 锁定比例、脸型、发型、服装、配色、耳鳍和鲸尾。
3. 基于母图和 Q 版动作参考生成动作首帧。
4. 后续帧使用母图、动作关键姿势和上一帧共同约束。
5. 只改变动作需要变化的局部。
6. 对序列执行身份、服装、比例、锚点和帧间抖动检查。
7. 去除背景、统一透明画布并按 manifest 命名。
8. 在实际 Helper 中播放，检查跳脚、变形和动作循环。

每个成品帧应记录使用的比例参考、动作参考和上一帧来源，便于重生成与追溯。

## 9. 错误处理

- 非法比例配置回退 `chibi`。
- manifest 缺失或格式错误时拒绝切换并保持当前画面。
- 单帧损坏时记录资产包、动作和路径，并按动作／整包层级回退。
- 切换期间不能清空当前 pixmap；新资产验证成功后才替换。
- 生成资产未通过透明度、尺寸、命名和连续性检查时不进入生产目录。

## 10. 测试与验收

### 10.1 自动测试

- 配置 schema 接受三个合法值并拒绝或归一化其他类型。
- 配置端点、Helper 启动环境与运行时消息正确传递比例。
- 布局存储保存、恢复并归一化 `characterProportion`。
- 三套 manifest 动作集合、帧数、文件存在性、尺寸和 RGBA 要求一致。
- 缺帧、坏 manifest、坏图片和未知比例均安全回退。
- 切换比例不改变当前 DSH 状态、活动分类和待办详情。
- 人格文案各分组非空、确定性选句稳定，关键事实不被改写。

### 10.2 视觉验收

- 三档默认显示总高度一致。
- 标准版约四头身，修长版约六至七头身。
- 切换形态时脚底、窗口和气泡不跳动。
- 所有连续动作无明显五官、服装、手指、鲸尾和比例漂移。
- 背景透明，无设计稿文字、边框或家具残留。
- 角色在 70%、100%、140% 尺寸下均不被裁切。
- 减少动态开启后仍使用正确比例资产，但停止不必要循环位移。

### 10.3 文案验收

- 用户可见自称为“小鲸鱼”，不再自称“大肥鱼”。
- 工作文案简洁且可理解；等待、成功和互动偶尔称“主人”。
- 项目名、阶段、待办、进度、错误和审批信息保持真实准确。
- 点击互动结束后恢复最新 DSH 状态，而非无条件回到空闲。

## 11. 实施顺序

1. 人格文案模块及测试。
2. 三档配置、协议、持久化与设置入口。
3. 多资产包 manifest、锚点、按需缓存、切换和安全回退。
4. 参考图预处理及标准版母图审核。
5. 标准版 50 帧生成、清理、验证与接入。
6. 修长版母图审核。
7. 修长版 50 帧生成、清理、验证与接入。
8. 自动测试、Helper 视觉验收、文档与兼容性检查。
